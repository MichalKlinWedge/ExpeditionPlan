# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ExpeditionPlan: AI trip planner. Web **Planner Hub** (`apps/web`, Next.js) for planning, Android app **Expedition Planner** (`apps/mobile`, Expo; called „Pocket Guide” in the spec) for the trip itself, offline-first. Backend: Supabase (Postgres + RLS + Realtime + Storage), web on Vercel. Built by one developer on the experience of FormaSync (`D:\AI\Kardio`).

Read before larger work:
- `SPECYFIKACJA.md` — the spec. §5 is the data model, §7 the schedule/constraint engine, §4 the AI pipeline, §0.2 why the model looks the way it does (it was derived from the user's real plans in `exaples/`).
- `PLAN_ETAPOWY.md` — stages (Etap 0 → PoC-0…5 → MVP-1…4 → v1.0). Each stage has an acceptance criterion; work toward it.
- `docs/USLUGI.md` — verified terms/limits of external services. Don't introduce a service it marks NIE (Google Places, MapTiler offline, tile.openstreetmap.org bulk).

All docs, UI strings and code comments are in **Polish**; identifiers in English.

npm run plan-ai -- --brief plik.json [--models claude-sonnet-5-5]   # brief downloaded from /trips/[id]/brief → out/<stamp>/szkic.json for „Importuj z pliku”; `claude -p` on the owner's subscription

Single test: `npx vitest run src/__tests__/structured.test.ts` (or `-t "nazwa testu"`) inside `packages/ai` or `packages/core`.

Mobile: always `npx expo install <pkg>` inside `apps/mobile` (SDK-compatible versions). Follow `apps/mobile/AGENTS.md` — check Expo SDK 58 docs, don't trust memory. Web: `apps/web/AGENTS.md` — read `node_modules/next/dist/docs/` before using Next APIs.

## Architecture rules

- **Domain logic lives in `packages/core`** and must run identically in the browser, on the phone (offline) and in Supabase Edge Functions (Deno). Keep it pure TS: no Node/Expo/Next imports outside tests.
- Packages are consumed as **TypeScript source** (`main: src/index.ts`), with **explicit `.ts` extensions in relative imports** — required by Deno. `allowImportingTsExtensions` is on everywhere; Next transpiles them via `transpilePackages`.
- **Zod schemas are the single source of truth** for form input, AI output, and `jsonb` columns. jsonb content is camelCase (Zod); table columns are snake_case.
- Time in plans = **local date/time + IANA zone** (`LocalDateTime` + `TimeZone`), never UTC instants. Real events (expenses, delays) use timestamptz. Money = integer minor units + ISO currency; plan prices use the `Price` schema (ranges, "from", age tiers).
- `packages/planner`: the „Zaplanuj z AI” chain (`planTrip`: stage 1 → day facts → stage 2 chunks → pins → place grounding → ORS travel times when `route` is given), pure TS with injected AI client, place lookup (`geoapifyLookup` in the app, cached Nominatim/Photon in tools) and holidays. Used by the web server action `planWithAi` (Gemini, D8) and by `tools/plan-ai`. The result is a NEW trip „Szkic AI: …” via `import_trip`; the user moves points into the real plan on `/trips/[id]/compare?draft=…` (`packages/core/src/plan-merge.ts` + `saveMergeEdit`; copied items are `source: 'ai'`, not `user_locked`). Server keys `GEMINI_API_KEY`, `GEOAPIFY_API_KEY`, `OPENROUTESERVICE_API_KEY` reach `apps/web/.env.local` through `scripts/sync-env.mjs` (no `NEXT_PUBLIC_` prefix → never in the browser).
- `packages/ai`: one client (`createAiClient`) over Claude/Gemini/OpenAI; keys come from config/env (server-side only — never in the browser or APK). Use `askStructured(client, schema, prompt)` for anything that becomes data: it validates with Zod and gets exactly one repair attempt. Model names are never guessed — `listModels()` is the source. With `failover` (the web's Gemini clients) a busy model (503/529/429) gets one retry, then cheap stand-ins from that list (`fallbackModels`: newest stable Flash-Lite, then Flash, never Pro).
- AI produces **drafts and patches, never silent overwrites**; user-edited items are `user_locked`.
- `packages/sync` (PoC-4): phone ↔ Supabase sync. Every write in a trip bumps `trips.sync_version` and stamps the row's `row_version` (trigger, serialized by the trip row lock); clients pull `row_version > last` via the `pull_changes` RPC (one snapshot). Phone writes (`schedule_events` append-only, `expenses`, `expense_splits`, `settlements`, `packing_checks`, `journal_entries` — `OutboxTable`) go through a SQLite outbox: local row + outbox entry in one transaction, idempotent upsert with client UUIDv7. No hard deletes — `deleted_at`. `LocalDb` is a sync interface (expo-sqlite in the app, `node:sqlite` in tests); the phone keeps server rows generically in one `rows (tbl, id, data)` table.
- **Schema (MVP-1)**: `supabase/migrations/*_mvp1_*.sql` = full §5 model (deviations in SPECYFIKACJA §5 „Odstępstwa w MVP-1”). Every `TripDocument` collection has a table with a `ref` column; common columns, version triggers, `activity_log` and RLS are added by loops in `mvp1_access.sql` — a new trip table goes into those arrays and into `synced_tables()`. `packages/sync/src/document.ts` (`SPECS`) is the only TripDocument ↔ rows mapping; a new document field needs a column there too (round-trip test over the 5 fixtures guards it). Whole documents are written via the `import_trip` RPC (one transaction, deferred FKs). Invites: `create_invite` / `accept_invite` (token hash only). Creating trips requires `app_metadata.trip_creator` (set only with the service key; `can_create_trips()` in RLS) — other accounts only see trips they were invited to; web AI/Geoapify/ORS actions additionally need the e-mail in `AI_ALLOWED_EMAILS`. Single-element writes outside the day plan (AI drafts stage 4/5, logistics editor) go through `saveElements` in `packages/sync/src/plan-save.ts`. After a migration: `npm run gen --workspace packages/db` (types), `npm run test:db` (pgTAP permission matrix).
- **Trip-time data outside `TripDocument`** (rows in `CachedTrip.live`, written via outbox): expenses + splits + settlements (`settle` in core: who owes whom, children to guardian, households), packing checks (shopping list = packing items in category `zakupy`, `core/meals.ts`; `items.self_cooked` marks meals cooked by the group), journal (`journal_entries`, photos in private bucket `journal`, phone queue in `features/trip/journal-photos.ts`). Receipt from a photo: phone `lib/web-api.ts` → web `POST /api/receipt` (Bearer session token, `AI_ALLOWED_EMAILS`, Gemini via `planner/src/receipt.ts`) → draft that fills the expense form. Calendar export: `/trips/[id]/calendar` (`core/calendar.ts`, ICS in UTC, UID per item ref). Budget vs spending per day (`core/budget-pace.ts`: day plan = lines pinned to the day's items + equal share of the rest; paid lines excluded) and weather go/no-go (`core/weather-alerts.ts`: bad forecast within 2 days + outdoor items; 19:00 reminder 2 days before). GPX tracks: the browser parses and simplifies the file (`core/gpx.ts`, ≤1500 points, DIN 33466 time) and `saveTrack` (`app/track-actions.ts`) at once stores the line in `tracks.geojson` (`DocTrack.geojson`) and replaces the item's km/time/ascent (`setItemRoute`, `user_locked`); `dayMap` draws it, phone `features/plan/track-card.tsx` shows position on the track offline. The lodging booking form sets the booking's place (name + coordinates or map link, `core/booking-place.ts`), which `dayLodging` prefers over `days.baseRef`. Foot routes from an external map: `core/item-route.ts` `setItemRoute` + `saveItemRoute` (link in `tracks.url`, typed km/time/ascent; the time goes into the item and drives the schedule, `user_locked` keeps „Przelicz przejazdy” off). Car legs get a plain Google Maps directions link (`drivingRouteUrl`, no API, nothing stored), replaced by an own `leg.routeUrl`; the web item editor sets from/to (`setLegRoute`, `components/item-leg.tsx`) and a change reroutes that item (`routeItem`; an end without coordinates is looked up by name, `locateLegEnds`, never guessed from neighbours). Never fetch those numbers from the Mapy.com API: its terms forbid storing results (`docs/USLUGI.md` §5). „Co nowego od ostatniej wizyty”: RPC `trip_news` (others' `activity_log` entries since `trip_members.seen_changes_at`; `touch_trip` moves it to the end of the previous visit after a >1 h gap, `mark_changes_seen` = „Przejrzane”), summarized by `packages/sync/src/news.ts`; card on `/trips/[id]`, banner above the phone trip tabs. „Gotowość do wyjazdu” on the same page until the trip ends: `core/trip-readiness.ts` (bookings to book/pay/without vault document, nights without lodging, undecided choices, open tasks, points off the map) + people without account/phone. Traveler start/end (`travelers.start_place_id`, `end_place_id`; typed name matches a trip place or creates one in `transportFields`, `app/actions.ts`) feed „Wspólny transport” on the people page (`core/traveler-transport.ts`); they count as place usage and are hidden from the public link. Per-traveler invite: `create_invite(..., p_traveler)` (single-use; `accept_invite` links the account to that traveler), „Zaproś” with a ready message on `/trips/[id]/people` (`FRIENDS_APK_URL` env = EAS install page, optional). „Wyślij e-mailem” there (`emailTravelerInvite`, `lib/mail.ts`) goes through SMTP from server env `SMTP_HOST/PORT/USER/PASS`, `MAIL_FROM`, also needed on Vercel; without them only copying is offered. Supabase Auth SMTP cannot be reused for own messages. Traveler uncertainty and partial attendance on the same page: `travelers.tentative`, `from_date`/`to_date` (`core/traveler-presence.ts`; no dates = whole trip, moved by `shiftTripDates`), `notes`; hidden from the public link, no effect on costs or schedule. Souvenir: `/trips/[id]/memories` (`core/trip-memories.ts` stats and route refs, journal photos, `Settlement`, printable with an SVG route trace); past trips sit in a collapsed „Archiwum” on both the web list and phone Wyjazdy, AI drafts (title prefix `Szkic AI: `, `isDraft`) in a collapsed „Szkice” at the very bottom. Postponed trips (`trips.status = 'postponed'`, `core/trip-status.ts`, set on the web trip page or in the new-trip form): own „Odłożone” section regardless of date, dates only tentative, no countdown, readiness or phone reminders. Rescheduling (web only): `core/trip-reschedule.ts` `shiftTripDates` decides what moves (days, unbought bookings, open absolute task dues, dated `decideBy`) and what stays as fact (bought bookings etc., listed in the preview with new engine warnings); `packages/sync/src/reschedule.ts` → RPC `reschedule_trip` writes it in one transaction, guarded by `sync_version`. A new date field in `TripDocument` must be decided there. Places page: `/trips/[id]/places` (`core/place-list.ts` usage and unused removal, `app/place-actions.ts`; coordinates through `pinPlace`, shared by every item using the place). Merging duplicates: `mergePlaces` repoints every reference (a new field pointing at a place goes there, a test over the fixtures guards it), `mergePlace` also moves `audio_guides`; `similarPlaces` only suggests. Removing a cancelled booking (web): `core/booking-remove.ts` clears every reference to it; a new field pointing at a booking goes there (a test over the fixtures guards it).
- **Sprzęt:** `/trips/[id]/gear` i zakładka „Sprzęt” na telefonie (`features/trip/packing-view.tsx`) to `packing_items` poza kategorią `zakupy`. Osobiste pakuje każdy (`assigneeRef` = tylko ta osoba), przy wspólnych o tym, kto bierze, decydują wiersze `packing_carriers` z ilością (rzecz można dzielić; spoza `TripDocument`, w `CachedTrip.live`, outbox `setCarrying`, prawa jak `packing_checks`: za siebie i swoje dzieci, organizator i edytor za każdego). `quantity = 0` to „nie biorę”. `assigneeRef` przy wspólnej (plan, import) liczy się jako osoba biorąca całość, póki nie ma własnego wiersza (`core/gear.ts` `gearCarriers`); opcjonalne `weightG` to waga sztuki do „Kto ile niesie” (`gearLoads`). Braki (`gearGaps`) trafiają do „Gotowości do wyjazdu”.
- **Posiłek przy punkcie:** `linkMeal` (`core/meals.ts`, wybór `MealLink` na „Posiłkach” i w edytorze planu) ustawia `parentRef` posiłku na punkt tego dnia. Posiłek stoi pod punktem, a jego godzina to `relative` od początku punktu (`from: previous` u podpunktu liczy się od rodzica). W odróżnieniu od innych podpunktów bloku posiłek kończący się później przesuwa następny punkt. Przy przejeździe to zwykły postój w trasie. Przesuwanie (`moveWithinDay`, `moveToDay`, `moveAfter`, `dropItem`) przenosi podpunkty razem z punktem (`carryChildren`).
- **Lodging items:** instead of a guide, the item card has „Obiekt”: a link to the property (`item.links`, `core/lodging-info.ts`) and data read by AI (`planner/src/lodging.ts`, Gemini) from text the user pasted, applied after a per-field preview (`applyLodgingDraft`; no booking on that day → a new one). Never fetch Booking.com pages: its terms forbid automated reading (A15), and partner APIs are out (SPECYFIKACJA W1).
- **Place guides (M8):** one `audio_guides` row per place (`content` jsonb = `GuideContent` in `core/guide.ts`). Built only from a Wikipedia article matched by name+coords (`planner/src/wiki.ts`; no confident match → no guide), images from Commons with licence/author; web actions `describeItem`/`describeTrip` (`app/guide-actions.ts`), card `/trips/[id]/item/[ref]`. Phone: `features/plan/item-details.tsx` (offline text, cached images, `expo-speech` read-aloud), guided walk = background task `features/walk/guide-walk.ts` (registered by import in `app/_layout.tsx`) notifying within 100 m.
- **AI cost rule:** only cheap models (Sonnet 5.5, Haiku 5.5) — `tools/plan-ai/src/pricing.ts` refuses others (Opus, Fable). The owner has no API credits; dev AI runs go through `claude -p` (`--backend claude-code`).
- `packages/core/src/engine/`: the schedule engine (§7) — `scheduleDay`, `proposeCuts`, `checkCarKmLimit`, `priceForGroup`, sun/moon, zoned time via `Intl` (no date libs). Computes on UTC instants, displays local time. „Trekking” and „pieszo” in the kind lists are `transport` with `leg.mode` `hike`/`walk`, not separate kinds (`core/item-kind.ts`). Moving an item (`moveWithinDay`, `moveToDay`, `dropItem`) clears a time that no longer fits its new position, unless it is `isFixed` or an exact booking time. Removing an item (`removeItemClosingGap`) moves the following timed items earlier by the freed time, down to the first such held time; an `exact` time without a booking moves too. `items.stopsMin` (stops/breaks, web and phone item editors) lengthens the item on top of its duration or leg time. `day.dayEnd` only warns (`after_day_end`) and counts toward slack; the web plan edits it per day (`setDayEnd`, „Planowany koniec dnia”). The phone plan shows the same numbers as the day map below it: tapping a number or card selects the pin and scrolls there (name = details). Plan times are "not earlier than"; `relative` + `from: previous` counts from the START of the previous item. A child (`parentRef`) of a `transport` item is a stop on the route (`core/route-stops.ts`): it lengthens the parent (drive + `stopsMin` + stops), shows only its duration and is left out of „now/next” and reminders; children of other items stay parallel blocks. A transport outside the counted day (another variant, skipped) is not a parent: its child runs as an ordinary point, and „↳ postój w trasie” (`routeStopTarget` with the viewed variant's options) can move it to the transport shown. The `bramka PoC-5` test keeps all five fixture plans within ±15 min — keep it green.

## Reference data

`fixtures/plans/<slug>/brief.json` are the user's five real trips as `TripBrief`; `plan.json` is the full hand-checked `TripDocument` (gold standard for AI import) and `GAPS.md` lists what the schema could not hold. `packages/core/src/__tests__/fixtures.test.ts` validates them — a schema change that breaks them is a regression. Gaps/inconsistencies found in the source docs are kept in `notes` on purpose.

## Conventions

- New files use LF (`.gitattributes` enforces `eol=lf`); never rewrite an existing file's line endings.
- Mobile is Android-only: don't add `*.web.tsx` variants.
- Distribution follows FormaSync: EAS channels `preview` (own phone) / `friends`, OTA with `runtimeVersion: appVersion` — bump `version` only together with a new APK. Current native set = APK 0.3.0 (0.2.0 added `expo-speech`, `expo-image-picker`; 0.3.0 adds `expo-brightness`); code importing a module outside the installed APK crashes on use, so a new native module always means version bump + `eas build` for both profiles before any OTA that uses it. Friends' install/update flow: `docs/ZNAJOMI.md`.
