# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ExpeditionPlan: AI trip planner. Web **Planner Hub** (`apps/web`, Next.js) for planning, Android app **Expedition Planner** (`apps/mobile`, Expo; called „Pocket Guide” in the spec) for the trip itself, offline-first. Backend: Supabase (Postgres + RLS + Realtime + Storage), web on Vercel. Built by one developer on the experience of FormaSync (`D:\AI\Kardio`).

Read before larger work:
- `SPECYFIKACJA.md` — the spec. §5 is the data model, §7 the schedule/constraint engine, §4 the AI pipeline, §0.2 why the model looks the way it does (it was derived from the user's real plans in `examples/`).
- `PLAN_ETAPOWY.md` — stages (Etap 0 → PoC-0…5 → MVP-1…4 → v1.0). Each stage has an acceptance criterion; work toward it.
- `docs/USLUGI.md` — verified terms/limits of external services. Don't introduce a service it marks NIE (Google Places, MapTiler offline, tile.openstreetmap.org bulk).

All other docs (everything except this file, which is mixed), UI strings and code comments are in **Polish**; identifiers in English.

## Architecture rules

- **Domain logic lives in `packages/core`** and must run identically in the browser, on the phone (offline) and in Supabase Edge Functions (Deno). Keep it pure TS: no Node/Expo/Next imports outside tests.
- Packages are consumed as **TypeScript source** (`main: src/index.ts`), with **explicit `.ts` extensions in relative imports** — required by Deno. `allowImportingTsExtensions` is on everywhere; Next transpiles them via `transpilePackages`.
- **Zod schemas are the single source of truth** for form input, AI output, and `jsonb` columns. jsonb content is camelCase (Zod); table columns are snake_case.
- **Shared labels, formatting, errors:** labels of schema values live in `packages/core/src/labels.ts` (`MEMBER_ROLE` — `owner` shows as „organizator”, `CONTACT_ROLE`, `ITEM_KIND`, `BOOKING_KIND`, `PRICE_BASIS`, `BUDGET_LINE_STATUS`, `NOTE_TOPIC`, `SLACK_LABEL`); don't redefine them in the apps. Formatting is in `packages/core/src/format.ts` (`plural`, `pluralForm`, `formatKm`, `dayLabel`, `dayLabelShort`, `dayChip`, `dayMonth`, `shortDate`, `capitalized`) plus `formatMinutes`, `formatMoneyRange`, `moneyToInput`, `fxLine`. A link meant for a human is `HttpUrl` (`schemas/common.ts`, http(s) only). Database errors shown to the user go through `dbErrorMessage` / `dbLoadError` (`packages/sync/src/remote.ts`); web actions load the trip with `pullTrip` and report schema errors with `validationError` (`apps/web/src/lib/trip-snapshot.ts`); `lockedRefs` (`packages/sync/src/document.ts`) lists the refs of `user_locked` items. On the Miejsca and Opisy miejsc pages changes sit behind „Edytuj” (`EditToggle`), as on Posiłki. Deleting a vault file from the bucket is a hard delete on purpose: the document is sensitive (`apps/web/src/components/vault.tsx`); journal files stay.
- Time in plans = **local date/time + IANA zone** (`LocalDateTime` + `TimeZone`), never UTC instants. Real events (expenses, delays) use timestamptz. Money = integer minor units + ISO currency; plan prices use the `Price` schema (ranges, "from", age tiers).
- `packages/planner`: the „Zaplanuj z AI” chain (`planTrip`: stage 1 → day facts → stage 2 chunks → pins → place grounding → ORS travel times when `route` is given), pure TS with injected AI client, place lookup (`geoapifyLookup` in the app, cached Nominatim/Photon in tools) and holidays. Used by the web server action `planWithAi` (Gemini, D8) and by `tools/plan-ai`. The result is a NEW trip „Szkic AI: …” via `import_trip`; the user moves points into the real plan on `/trips/[id]/compare?draft=…` (`packages/core/src/plan-merge.ts` + `saveMergeEdit`; copied items are `source: 'ai'`, not `user_locked`). Server keys `GEMINI_API_KEY`, `GEOAPIFY_API_KEY`, `OPENROUTESERVICE_API_KEY` reach `apps/web/.env.local` through `scripts/sync-env.mjs` (no `NEXT_PUBLIC_` prefix → never in the browser).
- `packages/ai`: one client (`createAiClient`) over Claude/Gemini/OpenAI; keys come from config/env (server-side only — never in the browser or APK). Use `askStructured(client, schema, prompt)` for anything that becomes data: it validates with Zod and gets exactly one repair attempt. Model names are never guessed — `listModels()` is the source. With `failover` (the web's Gemini clients) a busy model (503/529/429) gets one retry, then cheap stand-ins from that list (`fallbackModels`: newest stable Flash-Lite, then Flash, never Pro).
- AI produces **drafts and patches, never silent overwrites**; user-edited items are `user_locked`.
- `packages/sync` (PoC-4): phone ↔ Supabase sync. Every write in a trip bumps `trips.sync_version` and stamps the row's `row_version` (trigger, serialized by the trip row lock); clients pull `row_version > last` via the `pull_changes` RPC (one snapshot). Phone writes (`schedule_events` append-only, `expenses`, `expense_splits`, `settlements`, `packing_checks`, `journal_entries` — `OutboxTable`) go through a SQLite outbox: local row + outbox entry in one transaction, idempotent upsert with client UUIDv7. No hard deletes — `deleted_at`. `LocalDb` is a sync interface (expo-sqlite in the app, `node:sqlite` in tests); the phone keeps server rows generically in one `rows (tbl, id, data)` table.
- **Schema (MVP-1)**: `supabase/migrations/*_mvp1_*.sql` = full §5 model (deviations in SPECYFIKACJA §5 „Odstępstwa w MVP-1”). Every `TripDocument` collection has a table with a `ref` column; common columns, version triggers, `activity_log` and RLS are added by loops in `mvp1_access.sql` — a new trip table goes into those arrays and into `synced_tables()`. `packages/sync/src/document.ts` (`SPECS`) is the only TripDocument ↔ rows mapping; a new document field needs a column there too (round-trip test over the 5 fixtures guards it). Whole documents are written via the `import_trip` RPC (one transaction, deferred FKs). Invites: `create_invite` / `accept_invite` (token hash only). Creating trips requires `app_metadata.trip_creator` (set only with the service key; `can_create_trips()` in RLS) — other accounts only see trips they were invited to; web AI/Geoapify/ORS actions additionally need the e-mail in `AI_ALLOWED_EMAILS`. Single-element writes outside the day plan (AI drafts stage 4/5, logistics editor) go through `saveElements` in `packages/sync/src/plan-save.ts`. After a migration: `npm run gen --workspace packages/db` (types), `npm run test:db` (pgTAP permission matrix).
- **Trip-time data outside `TripDocument`** (rows in `CachedTrip.live`, written via outbox): expenses + splits + settlements (`settle` in core: who owes whom, children to guardian, households), packing checks (shopping list = packing items in category `zakupy`, `core/meals.ts`; `items.self_cooked` marks meals cooked by the group), journal (`journal_entries`, photos in private bucket `journal`, phone queue in `features/trip/journal-photos.ts`). Receipt from a photo: phone `lib/web-api.ts` → web `POST /api/receipt` (Bearer session token, `AI_ALLOWED_EMAILS`, Gemini via `planner/src/receipt.ts`) → draft that fills the expense form. Calendar export: `/trips/[id]/calendar` (`core/calendar.ts`, ICS in UTC, UID per item ref). Budget vs spending per day (`core/budget-pace.ts`: day plan = lines pinned to the day's items + equal share of the rest; paid lines excluded) and weather go/no-go (`core/weather-alerts.ts`: bad forecast within 2 days + outdoor items; 19:00 reminder 2 days before). GPX tracks: the browser parses and simplifies the file (`core/gpx.ts`, ≤1500 points, DIN 33466 time) and `saveTrack` (`app/track-actions.ts`) at once stores the line in `tracks.geojson` (`DocTrack.geojson`) and replaces the item's km/time/ascent (`setItemRoute`, `user_locked`); `dayMap` draws it, phone `features/plan/track-card.tsx` shows position on the track offline. The lodging booking form sets the booking's place (name + coordinates or map link, `core/booking-place.ts`), which `dayLodging` prefers over `days.baseRef`. Foot routes from an external map: `core/item-route.ts` `setItemRoute` + `saveItemRoute` (link in `tracks.url`, typed km/time/ascent; the time goes into the item and drives the schedule, `user_locked` keeps „Przelicz przejazdy” off). Car legs get a plain Google Maps directions link (`drivingRouteUrl`, no API, nothing stored), replaced by an own `leg.routeUrl`; the web item editor sets from/to (`setLegRoute`, `components/item-leg.tsx`) and a change reroutes that item (`routeItem`; an end without coordinates is looked up by name, `locateLegEnds`, never guessed from neighbours). Foot items without a saved link get a computed mapy.com link (`footRouteUrl`, documented `fnc/v1/route` address, the GPX line's waypoints when there is one; nothing stored), also as „Zaplanuj na mapy.com”. A GPX upload fills a missing from/to (`core/track-ends.ts` `setTrackEnds`: name „Trasa z A do B” from the mapy.com export, then a place right next to the end, otherwise a new place with the end's coordinates; a set end stays and only warns when far). Never fetch those numbers from the Mapy.com API: its terms forbid storing results (`docs/USLUGI.md` §5). „Co nowego od ostatniej wizyty”: RPC `trip_news` (others' `activity_log` entries since `trip_members.seen_changes_at`; `touch_trip` moves it to the end of the previous visit after a >1 h gap, `mark_changes_seen` = „Przejrzane”), summarized by `packages/sync/src/news.ts`; card on `/trips/[id]`, banner above the phone trip tabs. „Gotowość do wyjazdu” on the same page until the trip ends: `core/trip-readiness.ts` (bookings to book/pay/without vault document, nights without lodging, undecided choices, open tasks, points off the map) + people without account/phone. Traveler start/end (`travelers.start_place_id`, `end_place_id`; typed name matches a trip place or creates one in `transportFields`, `app/actions.ts`) feed „Wspólny transport” on the people page (`core/traveler-transport.ts`); they count as place usage and are hidden from the public link. The link gets only the number of tentative people (`public_trip.tentative`), never who. Per-traveler invite: `create_invite(..., p_traveler)` (single-use; `accept_invite` links the account to that traveler), „Zaproś” with a ready message on `/trips/[id]/people` (`FRIENDS_APK_URL` env = EAS install page, optional). „Wyślij e-mailem” there (`emailTravelerInvite`, `lib/mail.ts`) goes through SMTP from server env `SMTP_HOST/PORT/USER/PASS`, `MAIL_FROM`, also needed on Vercel; without them only copying is offered. Supabase Auth SMTP cannot be reused for own messages. Traveler uncertainty and partial attendance on the same page: `travelers.tentative`, `from_date`/`to_date` (`core/traveler-presence.ts`; no dates = whole trip, moved by `shiftTripDates`), `notes`; hidden from the public link, no effect on costs or schedule. Souvenir: `/trips/[id]/memories` (`core/trip-memories.ts` stats and route refs, journal photos, `Settlement`, printable with an SVG route trace); past trips sit in a collapsed „Archiwum” on both the web list and phone Wyjazdy, AI drafts (title prefix `Szkic AI: `, `isDraft`) in a collapsed „Szkice” at the very bottom. Postponed trips (`trips.status = 'postponed'`, `core/trip-status.ts`, set on the web trip page or in the new-trip form): own „Odłożone” section regardless of date, dates only tentative, no countdown, readiness or phone reminders. Rescheduling (web only): `core/trip-reschedule.ts` `shiftTripDates` decides what moves (days, unbought bookings, open absolute task dues, dated `decideBy`) and what stays as fact (bought bookings etc., listed in the preview with new engine warnings); `packages/sync/src/reschedule.ts` → RPC `reschedule_trip` writes it in one transaction, guarded by `sync_version`. A new date field in `TripDocument` must be decided there. All places across my trips, without AI drafts: `/places` (read-only, `core/place-list.ts` `placesAcrossTrips`, one row per place name unless far apart; button on the trip list; `?miejsce=<ref>` selects a place on the trip's page). Places page: `/trips/[id]/places` (`core/place-list.ts` usage and unused removal, `app/place-actions.ts`; coordinates through `pinPlace`, shared by every item using the place; under the square map the selected place's guide, `core/guide.ts` `placeGuide`, new one via `describePlaceGuide`, whose optional `which` says which of the same-named places is meant and stays in `content.hint` of the place's guide). Merging duplicates: `mergePlaces` repoints every reference (a new field pointing at a place goes there, a test over the fixtures guards it), `mergePlace` also moves `audio_guides`; `similarPlaces` only suggests. Removing a cancelled booking (web): `core/booking-remove.ts` clears every reference to it; a new field pointing at a booking goes there (a test over the fixtures guards it).
- **Dla kogo pozycja budżetu i wydatek:** `DocBudgetLine.participantRefs` (`budget_lines.participant_ids`, brak = wszyscy, także dodani później; komplet osób zapisuje się jako brak). „Na osobę” mnoży tylko przez wybranych (`lineTravelers`, też w `budgetPace`), a pozycja łączna dzieli się tylko na nich. `budgetSummary` daje `perTraveler`, a `perPersonLowMinor` jest `null`, gdy osobom wypada co innego: wtedy web i telefon pokazują kwotę każdej osoby. Wydatki: `expense_splits` jak dotąd, wybór w portfelu na telefonie i przy wydatku na webie (`setExpenseSplits`, wspólne `expenseSplitRows`); same wydatki dodaje się tylko na telefonie.
- **Waluta wyjazdu:** `trips.base_currency` zmienia się na „Rezerwacje i budżet” (`setTripCurrency`, `core/rates.ts` `rebaseRates`). Sumy, plan dzień po dniu i rozliczenie liczą się w niej, a kwoty pozycji i wydatków zostają w swoich walutach; kursy przechodzą przez kurs nowej waluty, a dawna dostaje własny. Kursy z telefonu są w pliku osobnym dla każdej waluty (`features/trip/live-rates.ts`).
- **Sprzęt:** `/trips/[id]/gear` i zakładka „Sprzęt” na telefonie (`features/trip/packing-view.tsx`) to `packing_items` poza kategorią `zakupy`. Osobiste pakuje każdy (`assigneeRef` = tylko ta osoba), przy wspólnych o tym, kto bierze, decydują wiersze `packing_carriers` z ilością (rzecz można dzielić; spoza `TripDocument`, w `CachedTrip.live`, outbox `setCarrying`, prawa jak `packing_checks`: za siebie i swoje dzieci, organizator i edytor za każdego). `quantity = 0` to „nie biorę”. `assigneeRef` przy wspólnej (plan, import) liczy się jako osoba biorąca całość, póki nie ma własnego wiersza (`core/gear.ts` `gearCarriers`); opcjonalne `weightG` to waga sztuki do „Kto ile niesie” (`gearLoads`). Braki (`gearGaps`) trafiają do „Gotowości do wyjazdu”.
- **Posiłki w wariantach:** strona „Posiłki” używa `mealList(doc, { allVariants: true })`: posiłki z niewybranych wariantów są na liście i mapie z nazwą wariantu, ale nie liczą się do porcji (`selfCookedTotals`), a kopie posiłku dla kolejnych knajp (`eatOutGroup`) zostają pod posiłkiem.
- **Posiłek przy punkcie:** `linkMeal` (`core/meals.ts`, wybór `MealLink` na „Posiłkach” i w edytorze planu) ustawia `parentRef` posiłku na punkt tego dnia. Posiłek stoi pod punktem, a jego godzina to `relative` od początku punktu (`from: previous` u podpunktu liczy się od rodzica). W odróżnieniu od innych podpunktów bloku posiłek kończący się później przesuwa następny punkt. Przy przejeździe to zwykły postój w trasie. Przesuwanie (`moveWithinDay`, `moveToDay`, `moveAfter`, `dropItem`) przenosi podpunkty razem z punktem (`carryChildren`).
- **Lodging items:** instead of a guide, the item card has „Obiekt”: a link to the property (`item.links`, `core/lodging-info.ts`) and data read by AI (`planner/src/lodging.ts`, Gemini) from text the user pasted, applied after a per-field preview (`applyLodgingDraft`; no booking on that day → a new one). Never fetch Booking.com pages: its terms forbid automated reading and partner APIs are out (`docs/USLUGI.md` §13 „Booking.com”, SPECYFIKACJA W1); the only Booking.com thing the code does is a search link (`planner/src/logistics.ts`).
- **Posiłki i lokale:** `/trips/[id]/meals` (`components/meals-view.tsx`) to układ jak w Miejscach: po lewej dni (`mealDays`), po prawej mapa (`mealMap`: numer na miejsce, posiłki w jednym lokalu mają ten sam) i dane knajpy pod nią, bez opisu samego miejsca. Knajpy przypina „Przypnij i zapisz” (`addEatOutChoices`): stają pod posiłkiem (`mealEateries`, `components/eat-out.tsx`); pierwsza jest miejscem posiłku, kolejna tworzy z nią wybór „gdzie jemy” (warianty), a knajpa będąca już w planie nie robi duplikatu. Knajpą jest miejsce z `places.venue` (`isEateryPlace`). `DocPlace.venue` to też punkty opisu (`venuePoints`; dawny `description` to pierwszy punkt), przykładowe ceny, ocena i `readOn`, z tekstu wklejonego przez użytkownika: `planner/src/venue.ts` (Gemini) robi szkic, a `core/venue-info.ts` dopisuje wiersze wybrane w podglądzie, nigdy nie kasując zapisanych. Po „Edytuj” punkty i ceny zmienia się i usuwa pojedynczo (`editVenuePoint`, `editVenuePrice`, `components/venue-entries.tsx`). Knajpa ze stroną ma też odczyt ze strony samego lokalu i jego menu, na kliknięcie (`lib/venue-site.ts`, `planner/src/venue-page.ts`: tylko sieć publiczna, `robots.txt`, bez serwisów pośrednich, `docs/USLUGI.md` §13). Nigdy nie pobieraj ocen ani cen automatycznie: warunki Google zakazują ich zapisywania także z Gemini Grounding (`docs/USLUGI.md` §3, §11). Na razie tylko web.
- **Place guides (M8):** one `audio_guides` row per place (`content` jsonb = `GuideContent` in `core/guide.ts`). `guide_library` is a shared cache across trips keyed by article (`GuideLibrary` in `planner/src/wiki.ts`): a ready text is copied into the trip without AI, only for guides without hint/`which` whose article bears the place's name; „Odśwież” (`fresh`) makes a new version, other trips keep their copy. Built only from an article matched by name+coords (`planner/src/wiki.ts`; no confident match → no guide), in order: pl and en Wikipedia by name, then by `coreName` (without plan additions, only with coords near the place), Wikidata links to an article in any language (`wikidataArticles`, needs coords within 15 km), Wikivoyage, then AI titles in any language, also from real articles within 1 km of the pin (`checkSuggestion`). When that fails the user gives a source (`GuideSourceForm`, `describeFromSource`): a Wikipedia/Wikivoyage link is an ordinary article, another page (read as in `docs/USLUGI.md` §13) or pasted text becomes `article.site: 'web'`: only a summary with a link is stored, no CC BY-SA and no images from that page. Images from Commons with licence/author; web actions `describeItem`/`describeTrip` (`app/guide-actions.ts`), card `/trips/[id]/item/[ref]`. All guides of a trip: `/trips/[id]/guides` (`core/guide.ts` `tripGuides`, `undescribedSights`, `components/guide-list.tsx`): new AI version after a confirmation, removal, manual text edits (`saveGuideText`, `editGuideText`, `content.edited`) and photos: remove, replace or add from the article or a Commons search (`findGuideImages`, `pickGuideImage`, `dropGuideImage`, `content.imagesEdited`; only Wikimedia files with a licence, `isWikimediaImage`). All of this changes only this trip's copy, never `guide_library`. The public link opens an overview collected from the plan without AI (`/p/[token]`, `core/trip-overview.ts` `tripOverview`: stats, map, highlights (only points with a guide and photo, no repeated title/article/photo, at most 2 a day, even count), days, stays, transport, open choices, warnings; free text loses sentences with amounts when costs are hidden, and goal/summary/warnings when names are hidden), the plan itself is at `/p/[token]/plan`. It shows guides too (`/p/[token]/item/[ref]`, shared `components/guide-article.tsx`; `public_trip` strips the AI hint and read-aloud data). Phone: `features/plan/item-details.tsx` (offline text, cached images, `expo-speech` read-aloud), guided walk = background task `features/walk/guide-walk.ts` (registered by import in `app/_layout.tsx`) notifying within 100 m.
- **AI cost rule:** default models are cheap ones (Sonnet 5.5, Haiku 5.5, `DEFAULT_RUN_MODELS`); Opus runs only when passed explicitly in `--models`; listed Gemini models are allowed; Fable and anything outside `ALLOWED_MODELS` in `tools/plan-ai/src/pricing.ts` is refused (`assertAllowed`). Production AI runs on Gemini (SPECYFIKACJA D8). The owner has no API credits; dev AI runs go through `claude -p` (`--backend claude-code`).
- `packages/core/src/engine/`: the schedule engine (§7) — `scheduleDay`, `proposeCuts`, `checkCarKmLimit`, `priceForGroup`, sun/moon, zoned time via `Intl` (no date libs). Computes on UTC instants, displays local time. „Trekking”, „pieszo” and „transport publiczny” in the kind lists are `transport` with `leg.mode` (`hike`/`walk`, `PUBLIC_MODES`), not separate kinds (`core/item-kind.ts`). Moving an item (`moveWithinDay`, `moveToDay`, `dropItem`) clears a time that no longer fits its new position, unless it is `isFixed` or an exact booking time. Removing an item (`removeItemClosingGap`) moves the following timed items earlier by the freed time, down to the first such held time; an `exact` time without a booking moves too. `items.stopsMin` (stops/breaks, web and phone item editors) lengthens the item on top of its duration or leg time. `day.dayEnd` only warns (`after_day_end`) and counts toward slack; the web plan edits it per day (`setDayEnd`, „Planowany koniec dnia”). The phone plan shows the same numbers as the day map below it: tapping a number or card selects the pin and scrolls there (name = details). Plan times are "not earlier than"; `relative` + `from: previous` counts from the START of the previous item. A child (`parentRef`) of a `transport` item is a stop on the route (`core/route-stops.ts`): it lengthens the parent (drive + `stopsMin` + stops), shows only its duration and is left out of „now/next” and reminders; children of other items stay parallel blocks. A transport outside the counted day (another variant, skipped) is not a parent: its child runs as an ordinary point. A point common to variants can be a stop in each: `parentRef` is the first transport, `routeParentRefs` the others (`itemsForDay` resolves the one counted), and „↳ postój w trasie” / „wyjmij z trasy” (`setRouteStop` with the viewed variant's options) change only the viewed variant. A new way of clearing `parentRef` must clear these too (`dropRouteParent`). The `bramka PoC-5` test keeps all five fixture plans within ±15 min — keep it green.

## Conventions

- New files use LF (`.gitattributes` enforces `eol=lf`); never rewrite an existing file's line endings.
- Web actions are never underlined text: `btn-mini` (edytuj, zmień, also inside a sentence), `btn-mini btn-mini-danger` (usuń), `btn-secondary btn-sm` (Anuluj, + Dodaj…). Going to another app page or downloading a file is a button too: `btn-secondary btn-sm` on its own, `btn-mini` inside a sentence. Underline only for external links and names in running text (a point in a list, a licence). Phone: `Button small`, `danger` for removal.
- Mobile is Android-only: don't add `*.web.tsx` variants.
- Distribution follows FormaSync: EAS channels `preview` (own phone) / `friends`, OTA with `runtimeVersion: appVersion` — bump `version` only together with a new APK (the APK version is `version` in `apps/mobile/app.json`; keep `package.json` equal). Current native set = APK 0.3.0 (0.2.0 added `expo-speech`, `expo-image-picker`; 0.3.0 adds `expo-brightness`); code importing a module outside the installed APK crashes on use, so a new native module always means version bump + `eas build` for both profiles before any OTA that uses it. Friends' install/update flow: `docs/ZNAJOMI.md`.
